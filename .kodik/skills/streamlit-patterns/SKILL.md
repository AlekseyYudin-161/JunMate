# Навык: Streamlit-паттерны JunMate

Специализируется на UI приложения на Streamlit: app.py, pages/*, экран загрузки, чат, превью
резюме, прогресс, сброс/фидбэк, PDF-вывод. Активируй при любой работе над интерфейсом.

## Инструкции
- Streamlit перезапускает скрипт на каждом действии. ВСЁ состояние — только в st.session_state (Profile, chat_history, track, gap, флаги). Глобальные переменные модуля для состояния НЕ использовать. init/reset — в core/state.py.
- Вход двумя путями в один пайплайн: st.file_uploader (PDF) ИЛИ st.text_area («нет резюме? опиши текстом») → один parser (A1) → Profile. Скан PDF без текста → понятная ошибка, без OCR.
- Honest progress bar: st.progress по реальным стадиям (парс 33% → трек 66% → gap 100%). Не имитировать плавный % внутри одного LLM-вызова.
- Чат: st.chat_message/st.chat_input, история в session_state. JSON-агенты НЕ стримятся (нужен цельный JSON для pydantic). Стриминг (st.write_stream) — только для текста ответа, как полировка; сначала нестримовый цикл с «думаю…».
- Стоп-кнопка (SHOULD, опционально): наивная не прервёт синхронный вызов; настоящий стоп — фоновый поток + очередь + st.fragment + threading.Event между чанками. Сложно — отложить, не блокировать ею остальное.
- Сброс диалога: st.dialog (подтверждение) → очистить session_state → st.rerun(). Фидбэк+баг — одна Google-форма через st.link_button, обе кнопки ведут на неё.
- Превью резюме: прокрутка + «Да, хорошо» (st.download_button → PDF) / «Нет, доделываем» (назад в чат).

## PDF-вывод (готча деплоя)
core/pdf_out.py: Profile/ResumeOutput → PDF. weasyprint (HTML+CSS) требует системные либы → на
Streamlit Cloud нужен packages.txt. Альтернатива без системных зависимостей — reportlab/fpdf2
(проще деплой, менее гибкая стилизация). Решить на старте, чтобы не переделывать.
